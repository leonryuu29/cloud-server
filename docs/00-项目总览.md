## 一句话
一台 2 核 2G 的阿里云学生服务器（北京）上，养了一条叫「大肥鱼」的 AI：
**AstrBot 框架 + DeepSeek 模型 + QQ 官方机器人 + 自己写的 MCP 工具箱**，

## 架构
```
 手机 QQ ──► QQ 开放平台 ──► AstrBot（systemd 常驻，/root/astrbot）──► DeepSeek API
                                    │  人格「大肥鱼」+ 课表
                                    │  定时任务（未来任务，Europe/Berlin）
                                    ▼
                           dafeiyu-mcp（stdio MCP，/root/dafeiyu-mcp）
              ┌──────────┬──────────┬──────────┬──────────┬──────────┐
            聊天日报    网易云品鉴   今日画廊    服务器状态   重要邮件
           (AstrBot DB) (pyncm)   (Safebooru)  (系统命令)  (WEB.DE IMAP)
                                    │
               cron：图库补货 / 听歌快照 / 每周备份 ──► 电脑每周日自动下载备份

 看门狗 watchdog.py（系统 cron 每 10 分钟，不用 AI）
   ├─ 读：AstrBot 数据库(任务运行时间) + 日志(有没有 Message sent) + systemctl/磁盘/图库
   ├─ 修：调 AstrBot 后台「立即执行」补发 / 重启 AstrBot / 补货 / 清临时图（都有次数上限）
   └─ 写：watchdog.log + 心跳 ──► 服务器日报显示「已补发」「自动修复 N 次」「看门狗心跳灯」

 邮件链路：
   Gmail ──WEB.DE 代收服务(约 2 分钟)──► WEB.DE 收件箱 ◄──IMAP── 邮件门铃 mail_check.py（系统 cron 每 10 分钟，德国 7–23 点，不用 AI）
                                                                  │ 有 48 小时内、且不是广告发件人的新邮件才叫醒（否则不花 token）
                                                                  ▼
                                          AstrBot「重要邮件」任务（不自动跑）→ 大肥鱼调 new_emails → 重要的才发 QQ

 电脑协作（09）：
   QQ「让电脑做…」→ 大肥鱼 pc_task_add → 任务队列 data/pc_tasks.json
   电脑 Codex / Claude ──ssh ecs "DAFEIYU_ROLE=pc server.py"（MCP over SSH）──► 领任务 / 读日报、状态、邮件（只读）
   pc_task_done ──► 后台 /run「电脑任务汇报」──► 大肥鱼 → QQ

 电脑 ──ssh ecs（密钥）──► 服务器      电脑 ──隧道 16185→6185──► AstrBot 后台
```

**三个角色别搞混**：
- **AstrBot**：大肥鱼的“身体”——收发 QQ 消息、调 DeepSeek、跑定时任务
- **dafeiyu-mcp**：大肥鱼的“手”——MCP 服务器，**大肥鱼（AI）主动调用**的工具（看日报、画廊、网易云、服务器状态）
- **看门狗**：大肥鱼的“自主神经”——**不是 MCP**，是系统 cron 定时跑的普通脚本，AI 不参与；从外面盯着 AstrBot，出问题直接动手修。反过来，服务器日报检查看门狗的心跳，两边互相盯
- **邮件门铃**：和看门狗同一个思路——先用便宜的代码“看一眼”，确实有事才叫醒 AI（规则 R11）

## 踩过的坑（重要经验）
- **定时任务必须明确要求调用 send_message_to_user**：只写在最终回复里的文字不会发给主人（11/22 早上叫床就是这样丢的）；上下文里的「[CronJob] …」只是内部记录，主人看不到
- **日报按夜猫子日算**：凌晨 0-5 点的消息算前一天
- **NapCat 官方停更**、Linux QQ 安装包下不了 → 改用 QQ 官方机器人（后台一键扫码，不需要国内手机号）
- **第一次扫码的密钥无效**（invalid appid or secret）→ 删掉适配器重扫
- **在错误目录启动 AstrBot** 会生成一份空白配置 + 随机密码 → systemd 固定工作目录
- **定时任务时区**：建任务时用的是旧时区，改系统时区后要逐个改（已改成 Europe/Berlin）
- **北京服务器网络**：Gmail、Pixiv、GitHub、插件市场都不稳/被墙；网易云、B 站、Safebooru、腾讯云 pypi 镜像能用
- **B 站**匿名接口会 -352 / 412 风控；关注列表要登录 → 放弃，换成网易云
- **AstrBot 的 API Key 没有 `system` 权限**，调不了「立即执行任务」接口 → 看门狗在服务器本机用 jwt_secret 现签 5 分钟令牌
- **自动修复一定要有刹车**：补发最多 1 次、重启 1 小时最多 1 次，否则一个坏任务会被无限重跑烧钱（规则 R9/R10，见 06）
- **QQ 邮箱授权码要中国手机号发短信**；Gmail IMAP 从北京直连时通时断（3 次通 1 次）→ 改用 WEB.DE 代收 Gmail（北京连 WEB.DE 稳定）
- **代收会把旧信陆续搬进来**：邮件编号是“搬进来的顺序”，不是邮件时间 → 只认「编号比上次大 **且** 邮件日期在 48 小时内」
- **测试不能动生产状态**：体检原来直接调 `new_emails`，会把“已读位置”往前推、吞掉真邮件 → 体检改成只看不推进
- **PowerShell 命令里写中文路径会乱码、而且可能不报错**：之前往 `T:\云服务器\dafeiyu-mcp` 的同步其实没成功 → 中文路径一律用 node 脚本或 Desktop Commander 的文件工具，拷完要核对（规则 R13）
- **Windows PowerShell 5** 读不了无 BOM 的 UTF-8 中文脚本 → 脚本里只写英文；ssh 命令里引号容易出错 → 先写脚本文件再 scp 过去执行
