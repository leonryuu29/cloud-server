# 测试与验收

> 目标：大肥鱼**自己能稳定跑**（不用人陪着测）、**出问题能自己修**、**少花 token**。
> 这份记录：怎么测、测过什么、结果如何、以后怎么验收。最后更新：2026-11-22 14:35（德国时间）

## 一、验收标准（四条）
| 标准 | 具体指什么 | 怎么检查 |
|---|---|---|
| **自动化** | 所有推送按时自己发；邮件来了自己判断、自己推；不需要人触发 | `acceptance.sh` 的「自动化」「送达」「邮件」 |
| **稳定** | 服务常驻、开机自启、MCP 在线、资源充足 | 「稳定」 |
| **自愈** | 推送没发出会补发；服务挂了会重启；监控程序自己也被监控 | 「自愈」+ 服务器日报的看门狗心跳灯 |
| **省钱** | 不用 AI 的地方不用 AI；上下文有上限；没新邮件不叫醒 AI | 「成本」 |

## 二、一键验收
```bash
ssh ecs
bash /root/dafeiyu-mcp/acceptance.sh     # 只读，约 30 秒，23 项，[PASS]/[WARN]/[FAIL]
```
- 检查 8 个方面：稳定 / 自动化 / 送达 / 自愈 / 邮件 / 数据 / 安全 / 成本
- **只读**：不发消息、不推进邮件位置、不改任何东西（规则 R12）
- 平时不用跑：每天 06:05 的服务器日报就是自动的“小验收”；改了东西之后、或者觉得不对劲时跑一次

## 三、测试分几层
| 层 | 是什么 | 什么时候跑 | 例子 |
|---|---|---|---|
| 冒烟测试 | 直接调一下函数，看能不能正常返回 | 每次改代码后 | `healthcheck.sh` 里的 [OK]/[FAIL] |
| 单元检查 | 单独测一个小逻辑 | 写新逻辑时 | `is_noise('LinkedIn <…@linkedin.com>') == True`，Google 发件人 == False |
| 端到端（E2E） | 从源头到手机，整条链路真实走一遍 | 新功能上线前 | Gmail 发信 → WEB.DE → 门铃 → 大肥鱼 → QQ |
| 故障演练 | 故意制造故障，看能不能自己修 | 加自愈能力时 | 故意不发消息的任务 → 看门狗补发 → 补发失败后放弃 |
| 验收 | 全面体检 + 对照验收标准 | 阶段完成时 | `acceptance.sh` |

**测试纪律**：测试数据标「[大肥鱼测试N]」；体检/验收只读；E2E 尽量走真实源头（从 Gmail 发，而不是直接塞进 WEB.DE）；能用代码断言的不靠肉眼。

## 五、省钱：token 花在哪、怎么省
| 环节 | 用不用 AI | 说明 |
|---|---|---|
| 看门狗（每 10 分钟） | ❌ | 纯代码 |
| 邮件门铃（每 10 分钟） | ❌ | 纯代码；**没有新邮件 / 全是广告 → 不叫醒 AI** |
| 旧邮件（几千封） | ❌ | 代码按日期过滤，AI 看不到 |
| 图库补货、听歌快照、备份 | ❌ | 纯代码 |
| 定时推送（每天约 13 次） | ✅ | 每次一轮 |
| 重要邮件判断 | ✅ | 只在有「非广告」新邮件时；一次最多 15 封、每封 300 字 |
| 和大肥鱼聊天 | ✅ | 正常对话 |

- **今天发现的最大隐患**：AstrBot 上下文上限原来是「不限」（`max_turns = -1`），聊天和所有定时推送在同一个对话里，历史越来越长 → 每次调用的输入从 2 千涨到 2 万 token。**已改成只保留最近 30 轮**（超了先裁最早的 10 轮）。日报统计读的是数据库聊天记录（`chat_history` 工具），不受影响
- 大部分输入命中 DeepSeek 缓存（今天 87%），缓存命中的价格便宜很多
- 实际花了多少钱：以 DeepSeek 控制台的余额/账单为准

## 六、已知局限
- 重要邮件最快几分钟、最慢约 10 分钟推到（WEB.DE 同步约 2 分钟 + 门铃每 10 分钟）；德国 0–7 点不推，早上 7 点统一处理
- 定时推送的 token 没进 AstrBot 的统计表（`provider_stats` 只记聊天）
- 广告发件人名单是手写的：新出现的营销邮件第一次仍会叫醒大肥鱼判断（它会忽略），常见的再加进 `mail_check.py` 的 `NOISE_DOMAINS`
- 服务器日报不能检查自己当天这一次（第二天才看得到）

## 七、以后怎么做测试（流程）
1. 改代码 → `py_compile` → 服务器上直接调一次函数（冒烟）
2. 推送类 / 邮件类 → 做一次 E2E：从真实源头发标了「[大肥鱼测试N]」的数据，**不手动触发**，等计划任务自己跑（等待时间写进记录）
3. 自愈类 → 故障演练：故意制造故障，看能不能修、会不会无限重试
4. 跑 `acceptance.sh`，结果贴到这份文档
5. 改进写进 `06-改进记录与规则.md`
